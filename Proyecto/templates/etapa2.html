01
CONTEXTO

Conjunto de datos y propósito

El archivo DatasetConsolidado.xlsx reúne tres tablas de datos con diferentes niveles territoriales. Estas tablas fueron seleccionadas durante la Etapa 1 para estudiar el crecimiento urbano y la transformación del suelo.

La información permite analizar el fenómeno desde una perspectiva global, nacional y regional, utilizando datos sobre forma urbana, cobertura del suelo, población, áreas y transiciones entre diferentes clases de cobertura.

Hoja Nivel Registros Variables Fuente
Global_Ciudades Global 200 79 Atlas of Urban Expansion — NYU / Lincoln Institute
Nacional_Colombia Nacional 24.396 16 MapBiomas Colombia, Colección 3.0
Regional_SabanaCentro Regional 39.672 18 MapBiomas Colombia, Colección 3.0
Total del libro: 64.268 registros y 1.120.232 celdas, considerando 113 columnas distintas.

Propósito del conjunto de datos

01

Escala nacional

Cuantificar cómo ha cambiado la cobertura del suelo colombiano entre 1985 y 2024, identificando las clases que ganan o pierden área.

02

Escala regional

Analizar la transformación del suelo en los 11 municipios de Sabana Centro, donde existe una importante presión urbana.

03

Escala global

Contextualizar el caso de Bogotá mediante la comparación de su forma urbana, densidad y patrón de expansión con otras ciudades.

Usuarios potenciales

Los principales usuarios pueden ser equipos académicos, investigadores, entidades de planeación territorial, CAR, Findeter, secretarías de planeación municipal y el propio equipo del proyecto.

El uso previsto corresponde a análisis estadístico agregado, series de tiempo y comparaciones espaciales, no al seguimiento de casos individuales ni a decisiones prediales puntuales.

02
CRITERIOS

Requisitos de calidad

Los requisitos se establecieron teniendo en cuenta el propósito del conjunto de datos y el tipo de análisis que se realizará posteriormente.

Requisito Justificación
Tipos de dato correctos Las hectáreas, población y tasas deben manejarse como números y los periodos como fechas para realizar cálculos.
Sin duplicados Cada registro debe representar una ciudad o transición única para evitar sobreestimar las áreas transformadas.
Categorías homologadas Las clases de cobertura deben coincidir con la Leyenda_Coberturas para permitir agregaciones correctas.
Completitud Las variables clave como area_ha, class_from, class_to, periodo y población deben estar disponibles.
Rangos válidos Las áreas no pueden ser negativas y año_fin debe ser mayor o igual que año_inicio.
Trazabilidad temporal Debe conocerse el periodo utilizado para evitar mezclar datos anuales con datos agregados.
Comparabilidad Deben documentarse las diferencias entre Global, Nacional y Regional para evitar comparaciones incorrectas.
Actualidad Las fuentes deben tener una fecha de referencia suficientemente reciente para el fenómeno estudiado.

Problema crítico identificado

El problema de mayor impacto corresponde al campo feature_id de Nacional_Colombia, debido a que los 24.396 registros tienen el mismo identificador.

La combinación class_from + class_to presenta 428 valores únicos y coincide con las transiciones documentadas, por lo que puede utilizarse como base para reconstruir el identificador.

ANÁLISIS

Análisis de causas

Problema Causa probable
feature_id constante Error de transformación durante el paso de formato ancho a formato largo. El identificador no se propagó correctamente durante el proceso ETL.
Números como texto La fuente original contiene números formateados para lectura humana, con separadores de miles y símbolos de porcentaje.
Fechas de dos dígitos Formato heredado M/D/AA sin normalización al consolidar la información.
"No observado" Limitación de MapBiomas relacionada con píxeles que no pudieron ser clasificados.
Mezcla de granularidades Decisión de la Etapa 1 al transformar los datos a formato largo sin agregar una advertencia o filtro obligatorio.
Encabezados inconsistentes Errores de digitación y ausencia de una normalización de encabezados durante la consolidación.
Valores atípicos Distribución naturalmente asimétrica de las transformaciones de cobertura.
Desactualización global El Atlas of Urban Expansion corresponde a un estudio puntual y no presenta actualización periódica equivalente a MapBiomas.
Clasificación de las causas: errores de ETL, formatos heredados, limitaciones de la fuente original y variabilidad real del fenómeno.
07
INTEGRACIÓN

Integración y homologación

El conjunto consolidado reúne fuentes originalmente independientes. Para permitir su uso conjunto se definieron criterios de homologación.

01

Unidad de área

Las tres hojas expresan las superficies en hectáreas (ha), por lo que no fue necesario realizar conversiones entre unidades.

02

Categorías

Nacional y Regional utilizan los mismos códigos de cobertura y fueron validados contra Leyenda_Coberturas.

03

Periodos

El campo tipo_periodo debe utilizarse como filtro antes de realizar sumas o promedios de area_ha.

04

Diferencias de escala

Global mide forma y densidad urbana, mientras Nacional y Regional miden transformaciones de cobertura del suelo.

05

Bogotá

Bogotá permite una referencia conceptual entre la escala global y la nacional, aunque no existe una unión directa celda a celda.

06

Encabezados

Se propone eliminar dobles espacios y corregir "Frgmentation" para facilitar el uso de los datos en código.

Importante: Global y Nacional/Regional no son directamente comparables celda a celda. La integración busca mantener una relación conceptual entre las escalas, no mezclar sus magnitudes.

SOLUCIÓN

Plan de tratamiento

El plan define las acciones necesarias para corregir problemas de calidad o controlar aquellos que no pueden corregirse directamente.

Problema Acción Resultado esperado
feature_id inservible Regenerar el identificador utilizando class_from + class_to. 428 identificadores únicos.
Números como texto Eliminar comas y símbolos "%" y convertir los valores a float. 52 columnas numéricas listas para cálculo.
Fechas ambiguas Aplicar una regla explícita de siglo y convertir las fechas a formato ISO. Fechas YYYY-MM-01 sin ambigüedad.
"No observado" Mantener la categoría, pero marcarla como dato no observado y excluirla de indicadores cuando corresponda. 57 registros correctamente identificados.
Mezcla de granularidades Utilizar tipo_periodo como filtro obligatorio para análisis temporales. Reducción del riesgo de doble conteo.
Encabezados inconsistentes Eliminar espacios dobles y corregir "Frgmentation". Encabezados consistentes.
Valores atípicos Crear una bandera de revisión en lugar de eliminar automáticamente los valores. Atípicos identificados sin perder información.
Fuente global desactualizada Mantener el dato y añadir una advertencia visible sobre su fecha de referencia. Uso transparente de la información.

Conclusión

El conjunto de datos presenta una base sólida para continuar con el proyecto, debido a que no se encontraron filas duplicadas ni nulos explícitos y las categorías de cobertura y rangos analizados presentan resultados válidos.

Los principales problemas están relacionados con tipos de datos, identificadores, formatos de fechas, granularidad temporal y nombres de columnas. Estos problemas pueden ser tratados mediante procesos de limpieza, estandarización y validación.

También existen dos situaciones que no deben solucionarse eliminando información: la mezcla de granularidades debe controlarse mediante filtros, mientras que la antigüedad de la fuente global debe documentarse para evitar interpretar sus datos como una situación actual.
